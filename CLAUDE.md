# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

A flat, two-script Python project that emits structured Iran economic datasets covering **36 calendar months: Dey 1401 – Azar 1404 (Jan 2023 – Dec 2025)**. There is no package, no dependency manifest, and no test suite — each script is self-contained, runs on the **Python 3 standard library only** (`csv`, `json`, `os`, `statistics`, `dataclasses`, `typing`), and on execution writes CSV + JSON outputs next to itself.

The two scripts are independent but share an identical 36-row Persian/Gregorian month grid:

- `iran_macroeconomic_indicators.py` — 14 macro series (CPI/PPI, NIMA & free-market FX, gold coin, M2, deposit rate, GDP, unemployment, Tehran housing, Brent, Iran oil production).
- `iran_construction_materials_prices .py` — 20 construction commodities priced in IRR/kg (steel, non-ferrous, cementitious, petroleum, aggregates, glass). **Note the space in the filename**; always quote it in shell commands.

`Arzbari_Smart_Calculator_Final Saturday.xlsm` and `iran_construction_materials_complete_database.xlsx` are downstream artifacts, not inputs — do not parse them to recover data, the source of truth is the Python scripts.

## Common commands

Both scripts are run directly; each one validates its data, then regenerates all of its outputs in the script's own directory (overwriting existing files). Quote the construction materials filename because of the embedded space.

```bash
python3 iran_macroeconomic_indicators.py
python3 "iran_construction_materials_prices .py"
```

Outputs regenerated by the macro script: `iran_macroeconomic_monthly.csv`, `iran_macroeconomic_monthly_fa.csv`, `iran_macroeconomic_metadata.json`.

Outputs regenerated by the materials script: `iran_construction_materials_monthly_prices.csv` (note: filename written by the script does not match the checked-in file `iran_construction_materials_monthly_prices .csv` which has a trailing space), `iran_construction_materials_monthly_prices_fa.csv`, `iran_construction_materials_monthly_prices_per_ton.csv`, `iran_construction_materials_data_quality.csv`, `iran_construction_materials_metadata.json`.

There is no lint, build, or test command. Validation runs as part of `__main__` in each script and prints warnings to stdout — treat a non-empty warning list as a failure when modifying data.

## Architecture

Both scripts follow the same five-stage pipeline, in this order:

1. **Month index** — `MONTH_INDEX: Tuple[(persian_month, persian_year, gregorian_month, gregorian_year), ...]` of length `N_MONTHS = 36`. This is the canonical time axis. Any new series must be exactly 36 entries aligned to this index. The two scripts duplicate this constant; if you change one, change the other.
2. **Metadata dataclasses** — `IndicatorMeta` / `MaterialMeta` (frozen dataclasses) plus `INDICATORS` / `MATERIALS` tuples and `_MAP`/`_CODES` lookups derived from them.
3. **Hardcoded data** — `MACRO_DATA` (macro script) and `_VERIFIED_PRICES` (materials script) are dicts of `code -> tuple of 36 numbers`, with rich source-anchor comments above each series. **Numbers come from cited sources in those comments** (SCI, CBI, IME settlement, TGJU, Bonbast, OPEC, World Bank, etc.); preserve and extend those comments when editing values.
4. **Validation** — `validate_macro_data()` / `validate_prices()`. These encode domain invariants you must keep satisfied:
   - Macro: CPI/PPI/M2 monotonically increasing; `fx_market >= fx_official` every month; `cpi_mom > 0`; Brent ∈ [40, 120] USD/bbl; every series has 36 points.
   - Materials: positive prices everywhere; `beam_ipe > rebar`, `sheet_cr > sheet_hr`, `sheet_galv > sheet_hr`, `copper > aluminum > zinc > lead`, `cement_white > cement_t2`, `sand >= gravel`; month-over-month moves capped at ±40%. The `rebar <= billet` case is intentionally emitted as INFO (export-premium / domestic-cap regime in late 1403–1404), not as a hard error — keep it that way.
5. **Emitters** — `generate_main_csv` (English headers), `generate_farsi_csv` (Persian, two header rows), `generate_metadata_json`, plus `generate_per_ton_csv` and `generate_quality_csv` for materials. All CSVs are written with `encoding="utf-8-sig"` so Excel renders Persian correctly — keep that BOM.

### Construction materials: verified vs. derived

The materials script intentionally separates two layers:

- `_VERIFIED_PRICES` holds 6 base series (`rebar`, `billet`, `aluminum`, `copper`, `cement_t2`, `bitumen`) sourced from IME settlement / TGJU / CODAL.
- `_derive_prices()` computes the other 14 by multiplying a base series by a per-month ratio array (also 36 entries). The ratio arrays encode market spreads (e.g. IPE ≈ 1.22–1.28 × rebar, CR sheet ≈ 1.65–1.95 × billet, zinc ≈ 0.35–0.38 × aluminum) calibrated against ISPA / Fouladban / TGJU bulletins. **When adding or correcting prices, prefer fixing a verified base or a ratio array over hand-editing a derived series**, otherwise the next regeneration will overwrite the change. `build_quality_flags()` then auto-stamps cells `V` (in `_VERIFIED_PRICES`), `M` (derived but IME-traded), or `E` (derived non-exchange).

### Conventions worth preserving

- All keys, column names, and identifiers are lowercase ASCII (`fx_market`, `sheet_cr`, `cement_t2`); Persian appears only in display strings via `name_fa` / `category_fa` / `PERSIAN_MONTHS_FA`.
- Units live in metadata, not in column data: macro series are mixed-unit (IRR, %, USD/bbl, …); materials are uniformly IRR/kg, with the per-ton CSV produced by `× 1000`.
- The `# fmt: off` / `# fmt: on` blocks guard the visual layout of the data tuples — leave them in place when running formatters, and keep one row per Persian year so the comment annotations (`# 1402`, `# Dey-Esfand 1403`, etc.) stay aligned with the index.
- Data updates should also extend the source-citation comments above each series; the metadata JSON pulls from `MACRO_DATA` / built tables but the provenance only lives in the comments.
